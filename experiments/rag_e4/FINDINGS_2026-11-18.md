# E4 findings — Roman Urdu style in the real backend (2026-11-18)

Branch `feature/urdu-transcripts`. First end-to-end run of the Urdu style work
through the product backend (sign-in → upload → profile → `/script/generate`)
on the GPU lab PC. All models local (Whisper, Ollama `qwen2.5:14b` / `3b`).

**Short version.** The pipeline works end to end. The first run exposed four
bugs in the new style-measurement code that made the evaluator push scripts
the wrong way. They are fixed and covered by tests. With 17 reels of one creator
(Hamza Bhatti) the scripts now take on his greeting, sign-off and Urdu–English
mix (18 scripts: overall 83.2 ± 5.7, all original). The content is still weak:
nonsense phrases, wrong facts, ASR misspellings copied into scripts. We do not
yet know whether the cause is the transcripts (ASR noise) or the model (14B
Roman Urdu). The next step is a root-cause experiment, before any fine-tuning.

Setup problems we hit, for the next person:

  (`500` on every call). Fix: re-run the installer in a real terminal. The
  systemd service looks for models in `/usr/share/ollama`. We disabled it and
  run `ollama serve` as the user, so it uses `~/.ollama`. This has to be
  restarted after every reboot.
- `Dockerfile.backend` pins `qdrant-client==1.9.1`, but the code needs ≥1.10
  (`query_points`). The venv uses 1.20. **The Docker image still needs this fixed.**
- `rapidocr_onnxruntime` is not installed, so caption/tone analysis in
  Module 2 is skipped (non-fatal).
- Upload limit: 10 videos per upload. `MAX_UPLOAD_VIDEOS` env override added
  (default unchanged) to test with 17.

## 2. Romanization check (Whisper small, 3 reels)

`romanize_transcripts.py` on v1 Hamza, `qwen2.5:14b` on GPU (~10–15 s/reel).

| Problem | Fix |
|---|---|
| Last chunk of 32 words: the model romanized half of it and copied the rest in Urdu script. The retry ran at the same temperature, so it gave the same answer. | A short tail is merged into the previous chunk. The retry raises the temperature. |
| The model sometimes writes academic transliteration (`mōṭa chāvl`, `ɪnjdɪnɪnt`) | `plain_latin()` strips accents/IPA. A prompt rule asks for plain a–z. |

Quality: the Roman Urdu reads like Instagram typing, and English words come
out in English. **The main error is upstream ASR**: Whisper `small` heard
"Peshawar" as "bishawar" and "criminal" as "paermonal". Whisper `large-v3` (used by
the backend) fixes many of these ("peshawar ka do sau saal purana nashta") but
not all ("driver kar rahay" for "try kar rahay").

## 3. Bugs found in the backend run, and fixes

The first `/script/generate` gave scores and feedback that were clearly wrong.
Each bug below is fixed and has a regression test (`tests/backend/test_urdu_style.py`).

| # | Symptom | Cause | Fix |
|---|---|---|---|
| 1 | Creator measured at **2% English**. Hamza mixes a lot. The evaluator told scripts "use more Urdu". | The lexicon counted any word missing from Whisper's English *translation* as Urdu. The translation paraphrases, so `video`, `food` and `restaurant` became "Urdu". | A word is English if it is in an English word list (`pipeline/data/english_words.txt.gz`, SCOWL, 64k) and not in the Roman Urdu lexicon. Short look-alikes (`bat` = baat, `rat` = raat) are learned per creator. Common Urdu words that are also English (`wale`, `bane`, `pure`) were added to the Urdu list. → Hamza: **~10%** |
| 2 | Creator sentence = **332 words**, 50% questions. Feedback said "use longer sentences". | Whisper's Urdu output has no punctuation, so a whole reel counted as one sentence. | When the Roman text is unpunctuated, sentence length and question share come from the English transcript. → **17–20 words, 6–10% questions** |
| 3 | Greeting "bhati armi" used as content ("bhati armi ki nihari"). | It was listed as a catchphrase. Openers needed the same first 3 words in 2 reels, which ASR spelling variants broke. | Openers/closers are phrases inside the first 6 / last 8 words of ≥20% of reels (min 2). A greeting split by ASR is joined ("bhati armi" + "pakhir raglay"). Its words are excluded from catchphrases. The prompt says to use it only at the start of scene 1. |
| 4 | Script sentences measured 56–78 words. | The LLM leaves out full stops, so 5 scenes became one sentence. | Each scene's voiceover ends a sentence when scoring. → 12–15 words |
| 5 | Scripts ended "… let me". | "comment below and let me know" was cut to a 2-reel "closer". | Covered by the ≥20% rule in #3. |
| 6 | Fragments tacked on ("… ko to bhai", "… kar rahay hain", "batao ke ar"). | Catchphrases were raw n-grams. | Drop phrases that start/end on a postposition (`ko`, `ke`, `mein`, `par` …), phrases made only of common grammar words, and phrases with an unknown 1–2-letter word at either end. Each catchphrase is shown with a ≤7-word example of how the creator says it. That is below the 8-word copy check. |
| 7 | Hook score fell to 0–2 after the greeting was added. | The greeting used the hook's word budget, and the judge scored "bhati armi pakhir raglay" as the hook. | The hook is measured and judged without the greeting (fuzzy match: "Bhati Armee" still counts). The prompt asks for the greeting, then a hook sentence. |
| 8 | ASR misspellings in catchphrases ("farsh bait" = first bite, "hum daray" = hum try) | They come from ASR. `qwen2.5:14b` cannot fix them on its own: tested, it gives "first **bait**" and "kaho **gi** sim ko andey". | Prompt note: the phrases come from speech recognition, so spell English words correctly. Quick check, 2 topics × 3 scripts (the §4.2 runs are without it): it does not fix spellings. "bhati armi" appears 6/6, "hum daray kar rahay hain" 3/6, "first bite" 0/6 ("farsh bait" also stopped appearing). Overall 84 (similar to §4.2). 2/6 failed the copy check, both on "bhati armi pakhir raglay hum daray kar rahay hain" (greeting + the creator's next words). Planned: creator review/edit of greeting and catchphrases (UI). |

Also: the copy check no longer counts the creator's catchphrases, greeting and
sign-off as copying, because the prompt asks for them.

### 4.2 Final configuration: 3 topics × 2 runs × 3 variants = 18 scripts

Topics: Lahore nihari shop, Karachi 500 vs 3000 biryani, Peshawar chapli kabab.
Hamza profile from 17 reels. All 18 scripts with scores: `results/e4_backend_scripts_2026-11-18.md`.

| Metric (0–10, overall 0–100) | Mean | SD | Min–Max |
|---|---|---|---|
| Overall | **83.2** | 5.7 | 74–92 |
| Style (measured vs creator) | 6.8 | 0.8 | 5.6–7.8 |
| Hook (LLM judge, rubric) | 6.9 | 2.1 | 2.9–9.2 |
| Structure (8 checks) | 9.9 | 0.3 | 8.8–10 |
| Timing (word budget) | 9.7 | 0.6 | 7.7–10 |
| Original (no 8-word copy) | **18/18** | | |

What the metrics mean:
- **Style**: closeness to the creator's sentence length, "you"-address,
  question share and English share. Measured, no LLM.
- **Hook**: fixed 6-question rubric, LLM judge. This is the only subjective metric,
  and it has the largest SD.
- **Structure**: 5 scenes, valid timecodes, ends near 0:30, hook 4–15 words,
  captions ≤8 words, no empty or repeated scenes, no copying.
- **Timing**: word count vs the creator's speech rate (Module 2, ~141 wpm),
  ±15% gets full marks.
- One run varies by about ±6 overall points (SD 5.7). Do not compare single runs.

Examples (best and typical):
- 91 · "bhati armi pakhir raglay kya fark hai 500 ki biryani se 3000 ki? / hum yahan karachi ki biryani ka comparison kar rahay hain, bhai / … / mujhe comments mein batao ke apna favourite kaun sa hai, tum kaho ge"
- 88 · "Bhati armi pakhir raglay, chapli kabab mein garam masala nahi lagta. / Iska asli raaz hai ke ek special masala mix use kartay hain. / … / Farsh bait mein kaho ge ke yeh kabab itni delicious kyun hai, mujhe comments mein batao."
- 77 · "… ye raaz ye hai ke chapli kabab ka sabse ziyada taste chicken ka meat hota hai …" (wrong fact)

### 4.3 What the numbers miss

The scores reward the voice (greeting, sign-off, mix, length). They do not
catch:
- **Nonsense Roman Urdu**: "galib ka qalam ki tarah", "shor ka shahenshah",
  "tareeqa-e-shami".
- **Wrong facts**: chicken in chapli kabab, "1800 se pehle ki shop".
- **ASR spellings copied**: "farsh bait", "hum daray kar rahay hain".
- **Repetition inside a scene** (Peshawar B).

A blind human test (planned in E2) is needed alongside the automatic scores.

## 5. Root cause: open question

The Urdu problems come from three layers:

| Layer | Example | Owner |
|---|---|---|
| ASR (Whisper) | "farsh bait", "bhati armi", "hum daray" | Whisper on Pakistani code-mixed speech |
| Romanization | spelling drift, rare dropped words | `qwen2.5:14b` |
| Script writing | nonsense phrases, wrong facts | `qwen2.5:14b` Roman Urdu + noisy examples |

**Decision:** do not switch to a bigger model. A ~27B model (~17 GB) would leave
no GPU memory for video generation on the same card. The direction is to find
the root cause, then fine-tune a **small** model (7–8B, QLoRA; ~5 GB to serve)
if it is needed.

Planned experiment (needs the human reference sheet):

| | ASR examples (now) | Clean examples (human-corrected) |
|---|---|---|
| `qwen2.5:14b` | done (§4.2) | ? |
| small model (7–8B) | ? | ? |

- Scripts get much better with clean examples → fix ASR / romanization
  (spelling correction, or fine-tune the romanizer).
- They stay poor with clean examples → the model is the cause → fine-tune a
  small model for Roman Urdu writing (data: corrected transcripts, public
  Roman Urdu text, and examples generated once, offline, by a larger local
  model).
- The same sheet gives WER for Whisper `small` vs `large-v3` (`asr_check.py score`).
